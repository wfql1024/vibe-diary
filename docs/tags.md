# 标签与标签关系

## 1. 数据模型

```
entries ──< entry_tags >── tags ──< tag_links >── tags
```

- `tags.name` 唯一（UNIQUE）：标签不允许重名。
- `entry_tags`：记录与标签的多对多关联。**增删改标签本身**会同步改动这张表。
- `tag_links`：标签之间的**有向**关系，方向按用户拖拽原样存储。**只影响检索，永远不动 entry_tags**。

## 2. 标签管理（右上角「标签管理」）

| 操作 | 行为 | 提示 |
|---|---|---|
| 增 | 名称已存在则拒绝，不重复创建 | 「标签 X 已存在」 |
| 删 | 从所有记录中移除该标签，并删除它的关系边（记录本身保留） | 先弹确认，并显示会影响多少条记录 |
| 改 | 改名；若新名称已被占用，询问 合并 / 取消 | 合并后：记录引用改挂到目标标签，关系边一并改挂，原标签删除 |

合并效果 = 这些记录加上目标标签、然后移除原标签（与需求表述一致）。
合并时若产生「自己连自己」的边，直接丢弃。

## 3. 记录的标签编辑

在「记录」列表里，每条记录下方：

- 标签右侧的 `×`：把该标签从**这条记录**移除（标签本身仍留在标签库里）。
- `＋ 标签`：输入已有标签（带下拉候选）或直接输入新名称，回车确认。
  库里没有的名称会**自动创建**，于是它也出现在标签管理与画布中。

## 4. 标签关系（「标签画布」）

- 工具条两种模式：`连线`（从一个标签拖到另一个标签）与 `移动`（拖节点调位置，位置存在 localStorage）。
- **A → B 的含义**：检索 B 时，把打了 A 标签的记录也一并显示出来。方向按拖拽方向存储（v2 迁移去掉了早期那条会把方向反转的 CHECK 约束）。
- **可以成环**：递归查询用 `UNION` 去重，成环只是让环上几个标签互为一体，不会死循环。
- 点箭头 → 确认框 → 删除该关系。
- 删除标签、或合并标签时，涉及它的关系边会自动清除或改挂。

### 关系是传递的

A → B、B → C 时，检索 C 会连带 A、B 的记录（传递闭包）。
因此关系等价于「把这些标签归成一类」，而不是只连一跳。

### 它不会做什么

关系是**查询期的扩展**，不写回数据：

- 一条记录只打了 A，建立 A → B 之后，这条记录的标签依然是 A，不会自动多出 B。
- 检索结果里每条记录只出现一次（`EXISTS` 判定，不做 N 次 UNION，天然去重）。

对应 SQL（`src/db.ts` 的 `listEntries`）：

```sql
WITH RECURSIVE matched(id) AS (
  SELECT id FROM tags WHERE name LIKE $1              -- 名称命中的标签
  UNION
  SELECT l.source_tag_id FROM tag_links l
    JOIN matched m ON m.id = l.target_tag_id          -- 递归收集指向它们的标签（UNION 去重=防成环死循环）
)
SELECT e.* FROM entries e
 WHERE e.content LIKE $1 OR e.title LIKE $1 OR e.date LIKE $1
    OR EXISTS (SELECT 1 FROM entry_tags et
                WHERE et.entry_id = e.id AND et.tag_id IN (SELECT id FROM matched))
```


### 画布的排布与动画

布局是逐帧推进的力导向松弛（位置式 + 全局降温 + 最后一道硬性分离），连续 5 帧位移 < 0.12px 自动停循环，
最多 260 帧后彻底冻结（约 4 秒）。纯数学部分抽在 `src/components/tagGraphLayout.ts`，可用 node 直接 import 验证。

| 力 / 机制 | 规则 |
|---|---|
| 圆-圆排斥 | 按关系远近分档：**直接相连 `r1+r2+34`**（保证连线至少 34px 看得见）；隔一跳 +28；同簇 ≥3 跳 +46；跨族群 +56；两个孤立标签之间再 +40 |
| 关系弹簧 | 直接相连的两圆吸到 `r1+r2+56`，强度 0.13；双向关系只算一次 |
| 线-圆避让（力） | 非端点圆到线段距离 < `半径+14` 时把圆推开 |
| 线-圆避让（绘制） | 边画成二次贝塞尔，迭代 3 轮绕开所有圆 |
| 线-线斥力 | 两条线之间的最小距离 30px，太近就整体平移推开（线也有体积） |
| 线-线不交叉 | 真交叉时把半径较小的端点镜像翻到另一侧 +14px（仅在前 220 帧生效，之后交给细节分离与曲线绕行） |
| 族群抱团 | 每个连通分量向自身质心收 3.5% |
| 椭圆重力 | 向画布中心，纵向 ×2.2 → 铺满 1200×760 |
| 降温 | `frames < 260 ? max(0.05, 1-f/260) : 0`，之后完全冻结 |
| **硬性分离** | 每帧最后跑 3 轮全量分离，保证"最小间隙"是硬约束（边界夹取 / 交叉翻转都不会再破掉它） |

其它约定：

- 箭头 `markerWidth/Height = 4.2`，始终指向 A → B；
- 双向关系（A→B 且 B→A）本质仍是一条连接，画成**双线**（两条平行细线、不带箭头），删除时两个方向一起删掉；
- 每条线下面垫 7px 白色描边。

实测（真实数据 44 个标签 + 41 条关系，node 直接跑 `tagGraphLayout.ts`）：

- 收敛 **236 帧（≈3.9 秒）**；冻结后再跑 120 帧，最大位移仅 **1.5px**（不会缓慢蠕动/旋转）；
- **最短可见连线 34px**；圆-圆最小间隙 34px；
- 曲线-圆最小间隙 **+15.2px**（没有线被圆压住）；41 条曲线之间 **0 处交叉**。

## 5. 计数文案：总数(自身+外部)

侧栏标签与画布节点用同一套文案（`src/db.ts: tagCountLabel`）：

- 没有外部贡献：只显示自身数，如 `178`
- 有外部贡献：`总数(自身+外部)`，如 `334(156+178)`，括号部分用蓝色

含义：自身 = 直接打了这个标签的记录数（`entry_tags` 计数）；外部 = 传递地指向它的标签带进来的、去重后的额外记录数。
所以「点标签 → 列表条数」与标签上的总数永远一致。

## 5.0 记录页的标签栏

- 列出**全部**标签（含自身 0 条、只靠关系聚合的标签，例如「娱乐」「学习」这类汇总标签）；
- 排序按**含标签关系后的总数**（`reach`）降序，相同再按名字；
- 记录页不再展示「标签关系」清单 —— 关系只在「标签画布」里看和改；
- 数量文案仍是 `总数(自身+外部)`，例如 `438(156+282)`。
## 5.1 搜索框语法（类 GitHub 的 tag: 写法）

搜索框是唯一的筛选入口，支持两种成分，可混用（之间是 AND）：

| 写法 | 含义 |
|---|---|
| `tag:暖暖` | 只按标签筛选（不做正文匹配），关系扩展照常生效：命中 334 条，与侧栏「暖暖 334(156+178)」完全一致 |
| `tag:"带 空格的名字"` | 名称含空格时用引号 |
| 其他任意文字 | 正文 / 标题 / 日期 / 标签名的混合匹配（标签名同样走传递闭包） |
| `tag:暖暖 今天` | 既有暖暖标签、正文/标题/日期又匹配「今天」 |

- 点一下侧栏标签 = 往搜索框插入一个 `tag:名称` 记号；再点同一个标签则移除（toggle）。
- 搜索框里的记号可以直接当文本删掉，删了即取消该筛选项。
- `tag:` 先按**精确名**匹配，找不到才退化为「名称包含」匹配（所以 `tag:暖` 也能用，但 `tag:暖暖` 只算暖暖本身）。
- 对应实现：`src/query.ts`（解析）+ `src/db.ts: searchEntries`（拼 SQL）。

- v1（migration 001）建的 `tag_links` 带 `CHECK (source_tag_id < target_tag_id)`，会把 `生活 → 健身` 这种反向拖拽存成 `健身 → 生活`。
