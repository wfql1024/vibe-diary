# 标签与标签关系

## 1. 数据模型

```
entries ──< entry_tags >── tags ──< tag_links >── tags
```

- `tags.name` 唯一（UNIQUE）：标签不允许重名。
- `entry_tags`：记录与标签的多对多关联。**增删改标签本身**会同步改动这张表。
- `tag_links`：标签之间的**有向**关系，方向按用户拖拽原样存储。**只影响检索，永远不动 entry_tags**。

## 2. 标签管理（右上角「标签管理」）

| 操作 | 行为 | 提示 |
|---|---|---|
| 增 | 名称已存在则拒绝，不重复创建 | 「标签 X 已存在」 |
| 删 | 从所有记录中移除该标签，并删除它的关系边（记录本身保留） | 先弹确认，并显示会影响多少条记录 |
| 改 | 改名；若新名称已被占用，询问 合并 / 取消 | 合并后：记录引用改挂到目标标签，关系边一并改挂，原标签删除 |

合并效果 = 这些记录加上目标标签、然后移除原标签（与需求表述一致）。
合并时若产生「自己连自己」的边，直接丢弃。

## 3. 记录的标签编辑

在「记录」列表里，每条记录下方：

- 标签右侧的 `×`：把该标签从**这条记录**移除（标签本身仍留在标签库里）。
- `＋ 标签`：输入已有标签（带下拉候选）或直接输入新名称，回车确认。
  库里没有的名称会**自动创建**，于是它也出现在标签管理与画布中。

## 4. 标签关系（「标签画布」）

- 工具条两种模式：`连线`（从一个标签拖到另一个标签）与 `移动`（拖节点调位置，位置存在 localStorage）。
- **A → B 的含义**：检索 B 时，把打了 A 标签的记录也一并显示出来。方向按拖拽方向存储（v2 迁移去掉了早期那条会把方向反转的 CHECK 约束）。
- **可以成环**：递归查询用 `UNION` 去重，成环只是让环上几个标签互为一体，不会死循环。
- 点箭头 → 确认框 → 删除该关系。
- 删除标签、或合并标签时，涉及它的关系边会自动清除或改挂。

### 关系是传递的

A → B、B → C 时，检索 C 会连带 A、B 的记录（传递闭包）。
因此关系等价于「把这些标签归成一类」，而不是只连一跳。

### 它不会做什么

关系是**查询期的扩展**，不写回数据：

- 一条记录只打了 A，建立 A → B 之后，这条记录的标签依然是 A，不会自动多出 B。
- 检索结果里每条记录只出现一次（`EXISTS` 判定，不做 N 次 UNION，天然去重）。

对应 SQL（`src/db.ts` 的 `listEntries`）：

```sql
WITH RECURSIVE matched(id) AS (
  SELECT id FROM tags WHERE name LIKE $1              -- 名称命中的标签
  UNION
  SELECT l.source_tag_id FROM tag_links l
    JOIN matched m ON m.id = l.target_tag_id          -- 递归收集指向它们的标签（UNION 去重=防成环死循环）
)
SELECT e.* FROM entries e
 WHERE e.content LIKE $1 OR e.title LIKE $1 OR e.date LIKE $1
    OR EXISTS (SELECT 1 FROM entry_tags et
                WHERE et.entry_id = e.id AND et.tag_id IN (SELECT id FROM matched))
```


### 画布的排布与动画

布局是逐帧推进的力导向松弛（位置式 + 全局降温 + 最后一道硬性分离），连续 5 帧位移 < 0.12px 自动停循环，
最多 260 帧后彻底冻结（约 4 秒）。纯数学部分抽在 `src/components/tagGraphLayout.ts`，可用 node 直接 import 验证。

| 力 / 机制 | 规则 |
|---|---|
| 圆半径 | **面积 ∝ 数量**（r = 84·√(n/max)）：数量比 = 面积比；数量 < 50 的按 50 算（小标签归成一档），半径夹在 22–84px（全圆面积约占画布 15%） |
| 入场 | 一次性全量加载（不再分批）；位置由 `seedNodes()` 按族群铺开 |
| 圆-圆排斥 | 按关系远近分档：**直接相连 `r1+r2+34`**（保证连线至少 34px 看得见）；隔一跳 +28；同簇 ≥3 跳 +46；跨族群 +56；两个孤立标签之间再 +40 |
| 关系弹簧 | 直接相连的两圆吸到 `r1+r2+56`，强度 0.13；双向关系只算一次 |
| 线-圆避让（力） | 非端点圆到线段距离 < `半径+14` 时把圆推开 |
| 线-圆避让（绘制） | 边画成二次贝塞尔，迭代 3 轮绕开所有圆 |
| 线被挡时 | 若一条线的直线上有别的圆挡着，就把这条线两端额外拉开 26px，让线尽量绷直（少弯=少抖） |
| 线-线斥力 | 两条线之间最小距离 30px：靠近平移推开；**已经交叉时改成各自绕中点反向微旋**（以前交叉距离≈0 被直接跳过，这是发散的主因） |
| 线-线不交叉（过程中） | 每帧按「越靠中间越严重」排序，只解最严重的 2 个；同一端点 40 帧冷却，避免来回抽搐；仅前 220 帧生效 |
| 线-线不交叉（兜底） | **动画跑到 25 帧（约 0.4s）只要还有交叉就先解一轮**，之后最多解到 3 轮，尽快让画面清晰；每轮：对 4 个端点做局部搜索（绕伙伴旋转 ±20/40/60 度、法向平移 40/70/110px、镜像越过对方、与伙伴交换位置），每次候选先做两轮硬分离再统计，只接受交叉确实变少的移动；单点挪不动时再做**整簇平移/旋转**（8 方向 × 70/120px、±20/40 度）；再与硬分离交替最多 2 轮，最后平滑过渡 |
| 族群抱团 | 每个连通分量向自身质心收 3.5% |
| 椭圆重力 | 向画布中心，纵向 ×2.2 → 铺满 1200×760 |
| 降温 | `frames < 260 ? max(0.05, 1-f/260) : 0`，之后完全冻结 |
| 静止后微动 | 稳定后不冻结，改为**低频呼吸**：每节点绕安息位置做 4.2/3.6px 的正弦位移，周期约 9 秒（不是快速抖动） |
| 悬停推力 | 鼠标压在标签上时，它与 1~2 跳邻居每帧被向外推 0.55/0.35/0.2px，鼠标移开后自动回弹 |
| 交叉缺口 | 几何上仍解不掉的交叉，渲染时在交点先垫一小块底色，后画的线呈现"从缺口跨过去"，视觉上不结死 |
| 边界 | 圆一律夹在画布内（留 5px 防描边被切）：每帧松弛末尾、兜底结束、tween、静止呼吸后都会 `clampToView()` |
| 重新排布 | 工具栏「重新排布」按钮：从族群种子重新铺一次并平滑过渡，用来快速复现/观察兜底 |
| 手动模式 | 关闭时把当前画面位置**固化**为手动位置（不回落网格），可自由拖；**重新打开**时引擎先对齐到你手动调过的当前位置，再从那里继续自动排布（不会瞬移回关闭前的坐标；之后仍会按力场缓慢漂移，这是自动模式本身的行为） |
| **硬性分离** | 每帧最后跑 3 轮全量分离，保证"最小间隙"是硬约束（边界夹取 / 交叉翻转都不会再破掉它） |

其它约定：

- 箭头 `markerWidth/Height = 4.2`，始终指向 A → B；
- 双向关系（A→B 且 B→A）本质仍是一条连接，画成**双线**（两条平行细线、不带箭头），删除时两个方向一起删掉；
- 每条线下面垫 7px 白色描边。

实测（示例数据，node 直接跑 `tagGraphLayout.ts`）：

- 收敛 **236 帧（≈3.9 秒）**；冻结后再跑 120 帧，最大位移仅 **1.5px**（不会缓慢蠕动/旋转）；
- **最短可见连线 34px**；圆-圆最小间隙 34px；
- 曲线-圆最小间隙 **+15.2px**（没有线被圆压住）；41 条曲线之间 **0 处交叉**。

## 5. 计数文案：总数(自身+外部)

侧栏标签与画布节点用同一套文案（`src/db.ts: tagCountLabel`）：

- 没有外部贡献：只显示自身数，如 `178`
- 有外部贡献：`总数(自身+外部)`，如 `260(180+80)`，括号部分用蓝色

含义：自身 = 直接打了这个标签的记录数（`entry_tags` 计数）；外部 = 传递地指向它的标签带进来的、去重后的额外记录数。
所以「点标签 → 列表条数」与标签上的总数永远一致。

## 5.0 记录页的标签栏

- 列出**全部**标签（含自身 0 条、纯靠关系聚合的汇总标签）；
- 排序按**含标签关系后的总数**（`reach`）降序，相同再按名字；
- 记录页不再展示「标签关系」清单 —— 关系只在「标签画布」里看和改；
- 数量文案仍是 `总数(自身+外部)`，例如 `260(180+80)`。
## 5.1 搜索框语法（类 GitHub 的 tag: 写法）

搜索框是唯一的筛选入口，支持两种成分，可混用（之间是 AND）：

| 写法 | 含义 |
|---|---|
| `tag:标签B` | 只按标签筛选（不做正文匹配），关系扩展照常生效：命中数等于侧栏该标签显示的总数 |
| `tag:"带 空格的名字"` | 名称含空格时用引号 |
| 其他任意文字 | 正文 / 标题 / 日期 / 标签名的混合匹配（标签名同样走传递闭包） |
| `tag:标签B 关键字` | 既带该标签、正文/标题/日期又匹配「关键字」 |

- 点一下侧栏标签 = 往搜索框插入一个 `tag:名称` 记号；再点同一个标签则移除（toggle）。
- 搜索框里的记号可以直接当文本删掉，删了即取消该筛选项。
- `tag:` 先按**精确名**匹配，找不到才退化为「名称包含」匹配（所以写标签名的一部分也能用，但写全名只算它自己）。
- 对应实现：`src/query.ts`（解析）+ `src/db.ts: searchEntries`（拼 SQL）。

## 6. 迁移与兼容

- v1（migration 001）建的 `tag_links` 带 `CHECK (source_tag_id < target_tag_id)`，会把 `标签A → 标签B` 这种反向拖拽存成 `标签B → 标签A`。
- v2（migration 002）重建该表，去掉 CHECK、保留方向；已有的边原样搬过去。
- 因此**v2 之前画的箭头可能方向是反的**：看到方向不对，删掉重画即可（数据层面无法还原原始方向）。
## 6. 日历视图

记录页顶部可切换：**列表 / 周 / 月 / 年 / 跨年**（默认列表）。切到日历时，界面自动定位到最近一条记录的日期。

| 视图 | 内容 |
|---|---|
| 周 | 7 列（周日→周六），每条记录一张卡片：主题（标签）、正文、标签 chips、完成状态；今天那列高亮 |
| 月 | 7×6 网格，每格用彩色小块显示当天记录的**主题**（取标签名），超过 4 条显示 `+N` |
| 年 | 12 个月各一张 mini 热力图，按当天**完成条数**分五档深浅；月份标题旁显示当月完成数 |
| 跨年 | 每 3 年一块，每块 12 个月格子的热力图，按当月完成条数着色；顶部显示该年完成总数 |

- 导航：`上一周/月/年/3 年`、`今天`、`下一…`，右上角是当前区间标签。
- 数据：周/月视图走 `listEntriesBetween(from, to)`（含区间首尾）+ `tagsForEntries`；年/跨年走 `dailyCompletedCounts(from, to)`（只统计 `status = completed`）。
- 年视图里"完成任务数量"= 当天 `completed` 条数；月视图的彩色块默认取该记录的第一个标签作为主题色。
## 7. 搜索与筛选（2026-11 改版）

标签与主题的筛选**不再写进搜索框**，改成搜索框右侧的两个按钮，点开是多选面板：

| 交互 | 行为 |
|---|---|
| 点一次 | **选中**（蓝底）：只保留命中该标签/主题的记录 |
| 再点一次 | **排除**（红框划线）：过滤掉命中该标签/主题的记录 |
| 第三次 | 取消，回到未选 |

自由文字的匹配范围会跟着筛选走：

| 生效的筛选 | 文字匹配范围 |
|---|---|
| 都没有 | 正文 / 标题 / 标签名（标签按关系传递闭包扩展） |
| 只有标签筛选 | 正文 / 标题（不再匹配标签名，标签范围已定） |
| 只有主题筛选 | 正文 / 标签名（不再匹配标题） |
| 两者都有 | 仅正文 |

- 主题 = 标题里第一个「：」之前的部分（没有冒号则取整条标题），与导入数据里的「粥 / SiEm / lolm / 暖暖」这类前缀一致。
- 搜索框与所有筛选之间是 AND。

## 8. 记录页布局（2026-11 改版）

- 主列：搜索行 → 视图切换（列表 / 周 / 月 / 年 / 跨年）→ 内容。
- 右栏：**选中那天的明细**（原先的标签云已移除，标签管理仍在顶栏）。点周视图的日头、月视图的格子、列表里的日期，都会切换右栏内容。

### 视觉约定（2026-11 修）

- 蓝色（`#2f6bff`）只用于**主操作按钮**与**选中/激活**状态；
- 次要按钮（视图切换、日历格子、筛选项…）一律带 `flat` 类，样式各自定义（白底/透明底 + 细边）；
- 热力图用绿系（`#dcebd9 → #4c8f52`），不再用蓝色色阶，避免整屏发蓝。
### 交互实现（2026-11 改）

- **整块可点**：周视图点日志整列任意位置都切换右侧明细；月视图点整格；年视图点月份块的**任何位置**都跳月视图。
- **事件委托**：日历里只有 4 个容器级 `onClick`（周 / 月 / 年 / 跨年），靠 `data-day`、`data-heat-day`、`data-month` 属性判断该跳哪里；年视图里"具体日期格子"优先于"整块月视图"。
- **性能**：`CalendarView` 用 `memo` 包住、`openFromCalendar` 用 `useCallback`；12 个月的格子矩阵只在年份变化时算一次（`useMemo`）；热力色阶提到模块级常量；`.cal-year-month` 用 `content-visibility: auto`，离开视口不绘制。

- **画布缩放**：`TagGraph` 用 `wheel` 监听（`passive:false`）改 `viewBox`，范围 40%–300%，工具栏显示百分比并可点回 100%。

## 14. 待办与完成状态（2026-11 末改）

- **完成 = 有完成时间**：`entries.completed_at`（`YYYY-MM-DD` 或 `YYYY-MM-DDTHH:mm`）；NULL 即未完成。迁移 004 把原来 `status = completed` 的行按记录日期补了完成时间。
- 列表每一行左侧是 ☑ / ☐；点击勾选写入当前时间；**晚于截止时间时会询问**「按截止时间记录 / 按当前时间记录」。
- 取消勾选：原本没有截止时间的，把完成时间挪到截止时间，再清空完成时间。
- 完成时间在「编辑记录」弹窗里可自由改（完成行：日期+时间，另有「现在 / 未完成」两个快捷）。
- **逾期（系统标签）**：不写库，前端按 `isOverdue()` 现算——已完成看「完成时间 > 截止时间」，未完成看「现在 > 截止时间」。与用户自己写的「逾期」标签互不影响。
- **今日(待办)**：日历工具条的「今天」改名为「今日(待办)」；选中日期是今天时，右栏在当日记录下面追加「待办」区块，列出所有未完成事项（有截止的排前面，没有截止的排后面），每条显示截止时间与逾期标记。
## 15. 单一日期的待办模型（2026-11 定稿）

- `entries.date` 是**唯一的日期时间**（`YYYY-MM-DD` 或 `YYYY-MM-DDTHH:mm`）：既是日记日期，也是完成时间；**NULL = 未完成**（迁移 005 重建表去掉 NOT NULL，并把 `completed_at` 合并进 `date`）。
- 完成 = `date IS NOT NULL`；`status` 列随写入同步（`completed` / `pending`），仅作兼容。
- 勾选：写入当前时间；晚于截止时 `window.confirm` 二选一（按截止 / 按当前）。取消勾选：没有截止就把 `date` 挪成 `due_at`，再置空 `date`。
- 逾期（系统标签，不入库）：`isOverdue()` —— 已完成看 `date > due_at`，未完成看 `now > due_at`；显示在列表行、右栏待办项、周视图卡片（红色「逾期」）、月视图色块（右侧红边）。
- 按天聚合统一用 `dayOf()`（`date.slice(0,10)`）；SQL 里用 `substr(e.date,1,10)` 比较/分组，因为 `date` 可能带时间。
### 逾期与到期预告（2026-11 末）

- 完成已过截止的记录时用自研 `ConfirmDialog`（三选一：按当前时间 / 按截止时间 / 取消），不再用 `window.confirm`。

- 右栏当日列表里，逾期条目带红色「逾期」标记。
